# Admin Sport Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a bilingual, sport-scoped admin that safely manages event content, media, results, standings, awards, and public presentation.

**Architecture:** Keep the existing Supabase normalized competition model and archive-only lifecycle. Add only mobile hero, gallery ownership/album, and structured scoring metadata; Server Actions remain the sole mutation boundary. `/admin` is global operations, while `/admin/sports/[slug]` scopes all relational management to a sport.

**Tech Stack:** Node 22, Next.js 16 App Router, TypeScript, React 19, Tailwind/CSS, Supabase SSR/Auth/Storage/Postgres, Node test runner.

**Spec:** `docs/superpowers/specs/2026-08-27-admin-sport-operations-design.md`

## Global Constraints

- Preserve Supabase SSR `getClaims()` plus `admin_users` authorization and RLS; never expose service-role keys.
- Archive records and retain Storage objects; do not add ORM, REST API, CMS/page-builder, or packages.
- Use `next/image`, native HTML controls/dialog, Lexend, VI/EN content, and 10 MB PNG/JPEG/WebP validation.
- Read matching `node_modules/next/dist/docs/` and current Supabase docs/changelog before Next/Supabase edits.
- Keep `/kv.png` desktop and `public/kv-mobile.png` mobile defaults; apply teal/cyan tokens sampled from `public/theme.png`.
